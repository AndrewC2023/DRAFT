\begin{abstract}
In this paper a method for augmenting the Rapidly-exploring Random Tree star (RRT*) algorithm introduced by Karaman \& Frazzoli \cite{doi:10.1177/0278364911406761}, such that 
it can plan in an uncertain dynamic environment, is presented. The innovation is primarily in the development of a grid management system capable of handling
multiple obstacle types including uncertain obstacles, such that the probability of a cell being occupied at a certain time can be calculated and passed to any planning system.
Notably this grid management system is capable of interfacing with any planner that calculates its own state in relation to time as it plans. This allows for a planning algorithm to
avoid future collisions, and avoid regions that a moving obstacle could occupy in the future, all while avoiding static obstacles as any conventional planner does.
\end{abstract}

\section{Introduction}
The path and motion planning problem is a fundamental problem in robotics and autonomous systems.
There has yet to be an extensive amount of work done on the problem of path planning in the presence 
of dynamic obstacles,
let alone uncertain dynamic obstacles as well. 
The development then of a system that can manage all these cases
at once is necessary to provide more flexibility
for the implementation of planners on autonomous systems to run a more robust and reliable system. 
Presented here is a Grid management system that is capable of managing certain and uncertain static obstacles
and certain and uncertain dynamic obstacles. The grid management system is capable of propagating dynamic
obstacles into the future a given amount of time with a given time step resolution and can determine the 
occupancy probability of a cell at a given time. This system can also sample many potential futures for a 
dynamic obstacle based on the random parameters and boundary conditions of said obstacle. By doing 
all of this within the grid management system, it can interface with any planner that calculates its time 
of travel to a node such that it can access the grid as it plans to ensure safe planning in a dynamic uncertain environment.
To demonstrate the effectiveness of this system, an RRT* algorithm that follows a set velocity to determine time
is paired with a path validation system that checks a bounding box for the size a vehicle for intersections with grid elements at
the desired time.

\section{Problem Definition}
Let \(\mathcal{X} \in \mathbb{R}^{n \times 1}\) where  \( n \in \mathbb{N} \) denote the \(n\)-dimensional space and one time dimension configuration space that a vehicle is operating within. 
\(\mathcal{X}_{obs} \in \mathcal{X}\) denotes the set of occupied space and time. 
\(\mathcal{X}_{free} = \mathcal{X} \setminus \mathcal{X}_{obs}\) denotes the set of free space and time. 
Let the initial state and goal be denoted by \(x_{init}, x_{goal} \in \mathcal{X}_{free}\) respectively. 

Define the vehicle \(V\) as the space confined by a polygon \(V_{poly}\) with vertices \(\{v_1, v_2, \ldots, v_n\}\) in \(\mathbb{R}^n\). 
The position and orientation of the vehicle at any time \(t\) can be represented by a transformation \(T(x, V)\), 
where \(x\) is a state in \(\mathcal{X}\) and \(T(x, V)\) is a translation and rotation applied to \(V\). 
The transformed vehicle \(V_{transformed} = T(x, V)\) represents the space aligned with the vehicle's position and orientation in the 
configuration space \(\mathcal{X}\). Note that for path planning to be possible \(T({x_{init}, x_{goal}},V) \in \mathcal{X}_{free}\) must be true.

A dynamic obstacle \(\mathcal{O}\) can be defined similarly to a vehicle as the space with a polygon \(\mathcal{O}_{poly}\) with vertices \(\{o_1, o_2, \ldots, o_n\}\) 
in \(\mathbb{R}^n\) with dynamics that define some state function \(x_{obs}(t)\). 
Then, \(\mathcal{X}_{obs} \supset T(x_{obs}(t), \mathcal{O})\). 

An Uncertain dynamic obstacle can mean that the polygon defining the obstacle \(O_{poly}\) is not known exactly and/or the
the state function \(x_{obs}(t)\) is a function of random variables. In this case we define a new \(\mathcal{X}_{uncertain} \in \mathcal{X}\) 
for spaces that have a nonzero but less than or equal 
to one probability of occupancy, therefore \(\mathcal{X}_{obs} \subset \mathcal{X}_{uncertain}\).

Both static certain and uncertain obstacles can be defined in the same way as dynamic obstacles, but with a state function that is invariant with time.

The goal of a path planner is to find a path \(\mathcal{P} = \{x_1, x_2, \ldots, x_n\}\) as a list of states defined such 
that \(x_1 = x_{init}\), \(x_n = x_{goal}\), and \(T(\mathcal{P}, V) \subset \mathcal{X}_{free}\).

\section{RRT* Algorithm and Grid Management System}
For an RRT* planning algorithm let \(\mathcal{T} = \mathcal{T}(\mathcal{V},E)\) define the tree where \(\mathcal{V}\) are 
the vertices and \(E\) are the edges. let \(N \in \mathbb{N}\) denote the number of samples
that that the algorithm will take to plan. Let \(r\) define the maximum edge length for a tree. a discrete cost function 
to some horizon \(\ell\) is conventionally defined generally as:
\[
J = c_\ell(x_\ell) + \sum_{t=0}^{\ell-1} c_t(x_t, u_t)
\]
where \(c_\ell(x_\ell)\) and \(c_t(x_t, u_t)\) are local cost functions for the discrete space and \(x\) is a state and \(u\) is an input. 
The first term then is the cost at the
horizon and the second term is the cost to said horizon. When applied we can define our cost function \(c(x_t, u_t)\) in any way we like
to tune or guide a planner to minimize this function over \(\mathcal{X}\). to follow this structure a planner will have to implement the 
cost function such that it is summed with all parent nodes
to the current node (the horizon) in this case.
    
Let \(\mathcal{G}\) represent the configuration space \(\mathcal{X}\) voxelized into cells that contain information on probability of being occupied,
location, and cell size, along with methods to manage the space and how obstacles interact with it. The algorithms and system structure are as follows:

\begin{algorithm}[H]
    \caption{RRT*}\label{alg:rrtstar}
    \KwIn{$x_{init}$, $x_{goal}$, $N$}
    \KwOut{$\mathcal{P}$ from $x_{init}$ to $x_{goal}$}
    $\mathcal{T} \gets \{x_{init}\}$\;
    \For{$i \gets 1$ \textbf{to} $N$}{
        $x_{rand} \gets \text{SampleRandomState}()$\;
        $x_{nearest} \gets \text{NearestNeighbor}(\mathcal{T}, x_{rand})$\;
        $x_{new} \gets \text{Steer}(x_{nearest}, x_{rand}, r)$\;
        \If{$\text{Validator.CollisionFree}(x_{nearest}, x_{new})$}{
            $cost_{new} \gets \text{costFunction}(x_{nearest}, x_{new}) + \mathcal{T}.\text{at}(x_{nearest}).\text{cost}$\;
            $time_{new} \gets \text{timeToTravel}(x_{nearest}, x_{new}) + \mathcal{T}.\text{at}(x_{nearest}).\text{time}$\;
            $\mathcal{T}.\text{addNode}(x_{nearest},x_{new}, cost_{new}, time_{new})$\;
            $X_{near} \gets \text{Near}(\mathcal{T}, x_{new}, r)$\;
            $\text{Rewire}(x_{new}, X_{near})$\;
        }
    }
    \While{$\text{currentNode} \neq x_{init}$} {
        $\mathcal{P}.\text{push\_front}(\text{currentNode})$\;
        $\text{currentNode} \gets \mathcal{T}.\text{parent}(\text{currentNode})$\;
    }
    \Return $\mathcal{P}$\;
\end{algorithm}

\begin{algorithm}[H]
    \caption{Rewire()}\label{alg:Rewire}
    \KwIn{$x_{new}$, $X_{near}$}
    \ForEach{$x_{near} \in X_{near}$}{
        $cost_{near} \gets \text{costFunction}(x_{new}, x_{near}) + \mathcal{T}.\text{at}(x_{new}).\text{cost}$\;
        $time_{near} \gets \text{timeToTravel}(x_{new}, x_{near}) + \mathcal{T}.\text{at}(x_{new}).\text{time}$\;
        \If{$cost_{near} < \mathcal{T}.\text{at}(x_{near}).\text{cost}$}{
            $\mathcal{T}.\text{at}(x_{near}).\text{parent} \gets x_{new}$\;
            $\mathcal{T}.\text{at}(x_{near}).\text{cost} \gets cost_{near}$\;
            $\mathcal{T}.\text{at}(x_{near}).\text{time} \gets time_{near}$\;
        }
    }
\end{algorithm}
\begin{algorithm}[H]
    \caption{CostFunction()}\label{alg:CostFunction}
    \KwIn{$x_{1}$, $x_{2}$}
    $\text{distance} \gets \text{norm}(x_{1} - x_{2})$\;
    $\text{collisionProbability} \gets \text{Validator.getCollisionProbability}(x_{1}, x_{2})$\;
    \Return $\text{distance} + \text{collisionProbability} * PunishmentConst$\;
\end{algorithm}

\begin{algorithm}[H]
    \caption{Validator}\label{alg:validator}
    \KwIn{$x_{1}$, $x_{2}, Probability\&, \mathcal{V}, time$}
    $PathPolygon \gets \text{extendPolygon}(T(\{x_{1}, x_{2}\}, \mathcal{V}))$\;
    \ForEach {$\mathcal{C} = \mathcal{G}.\text{cell}.\text{at}(time) \in \mathcal{X}_{uncertain}$}{
        \If{$\mathcal{C} \cap (PathPolygon)$}{
            \If{$\mathcal{C} \in \mathcal{X}_{obs}$}{
                \Return false\;
            }
            \Else{
                \If{$\mathcal{C} \cap \mathcal{X}_{uncertain} \neq \emptyset$ $\mathbf{and}$ $\mathcal{C}.\text{probability} > Probability$}{
                    $Probability \gets \mathcal{C}.\text{probability}$\;
                }
            }
        }
    }
    \Return true\;
\end{algorithm}

\begin{algorithm}[H]
    \caption{Grid Management System}\label{alg:grid}
    \KwIn{$\mathcal{X}$, $\mathcal{X}_{obs}$, $\mathcal{X}_{uncertain}$, $\{\mathcal{O}_1, \mathcal{O}_2, \ldots, \mathcal{O}_n\}$}
    \KwOut{Updated $\mathcal{G}$ with obstacle information}
    $\mathcal{G} \gets \text{UpdateWithGivenInputs}(\mathcal{X}, \mathcal{X}_{obs}, \mathcal{X}_{uncertain})$\;
    \ForEach {$\mathcal{O} \in \{\mathcal{O}_1, \mathcal{O}_2, \ldots, \mathcal{O}_n\}$} {
        \ForEach {$t \in \text{timeRange}$} {
            \If{$\mathcal{O}$ is certain}{
            $x_{obs}(t) \gets \mathcal{O}.\text{state}(t)$\;
            $O_{transformed} \gets T(x_{obs}(t), \mathcal{O}_{poly})$\;
            \Else{
                $x_{obs}(t) \gets \mathcal{O}.\text{SampleStates()}(t)$ \tcp{generates futures for dynamic Obstacles}
                $O_{transformed} \gets T(x_{obs}(t), \mathcal{O}_{poly})$\;
            }}
            \ForEach {$\mathcal{C} \in \mathcal{G}.\text{cells}$} {
                \If{$\mathcal{C} \cap O_{transformed} \neq \emptyset$} {
                    \If{$\mathcal{O}$ is certain} {
                        $\mathcal{C}.\text{setOccupied}(t)$\;
                    } \Else {
                        $\mathcal{C}.\text{updateProbability}(t, \mathcal{O}.\text{probability})$\;
                    }
                }
            }
        }
    }
    \Return $\mathcal{G}$\;
\end{algorithm}

\section{Results}
An RRT* algorithm will yield a path that continues to converge towards the optimal path with more iterations. Of interest when using the algorithm layout in \textbf{Algorithm \ref{alg:rrtstar}} several functions can
be modified to affect the behavior of the algorithm. the standard implementation of RRT* with a static grid yields a path and search tree resembling arms reaching out from the start point like in \textbf{Figure \ref{fig:one}}. However
by interchanging processes within the algorithm different behaviors can be achieved for example the implementation in \textbf{Figure \ref{fig:two}}. However RRT* algorithms can also
be augmented with vehicle dynamics to change the steer function to improve path feasibility. The grid management has been designed to maintain this modularity and further the capabilities for any planner that
determines time to travel as well.

\section{Conclusion}
It is shown that using this grid system, a safe path, in a dynamic environment can be determined even when the future is uncertain. Among the need for more testing to quantify
robustness, runtime, efficiency, and comparison with other appraches, the current work can use further development for the implementation of more complex dynamics for both obstacles and vehicles,
requiring the creation of a dynamics class to manage the behavior of these items on its own. Optimizations of the sampling system are necessary as well and should likely include a polynomial chaos expansion
of the solved dynamic equations to reduce the number of required samples to converge on the predicted future probability field.
